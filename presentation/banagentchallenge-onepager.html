Arquitectura del pipeline agéntico

FIG. 02 — LANGGRAPH

Un grafo de estados explícito de cuatro nodos secuenciales — no una sola llamada a un LLM con un prompt largo. Cada nodo tiene una responsabilidad única y es observable de forma independiente.

NODO 01

Guardrails de entrada

Detecta prompt injection e instrucciones maliciosas antes de tocar el resto del grafo.

NODO 02

Clasificación de intención

Resuelve anáforas usando historial de sesión ("¿y cuánto tiempo estuvo ahí?" → Teradata).

NODO 03

Retrieval consciente de intención

Filtra Qdrant por tipo de chunk (MatchAny) y sanitiza saludos antes de vectorizar.

NODO 04

Generación fundamentada

Groq genera la respuesta anclada al contexto recuperado; si hay 0 chunks, bloquea la generación libre.

Qdrant Cloud · 384d · coseno Groq LPU (Llama 3.3 / 3.1) + HF Router fallback Supabase Postgres · checkpoints de sesión Langfuse Cloud SDK v3 · tracing Prometheus + Grafana Cloud · métricas FastAPI · slowapi rate limit 60 req/min

Flujo completo de una consulta

  1. Request llega a /v1/responses con session_id o previous_response_id. FastAPI valida la API key y el rate limit.
  2. Checkpointer de Supabase recupera el estado de la conversación asociado a esa sesión — el historial no se reenvía completo desde el cliente, vive en Postgres. PostgresSaver
  3. El grafo de LangGraph corre sus 4 nodos (guardrails → intención → retrieval → generación), y cada nodo emite un span. Langfuse CallbackHandler
  4. Qdrant se consulta con filtro MatchAny según la intención clasificada; se registran los chunk_ids y el top_score obtenidos.
  5. Groq genera la respuesta anclada al contexto recuperado; Prometheus incrementa contadores de tokens, costo estimado y duración por nodo en paralelo.
  6. El nuevo estado se persiste de vuelta en Supabase y la traza completa del turno queda cerrada en Langfuse Cloud, lista para auditoría.

Por qué Postgres y no memoria en RAM

Render reinicia o duerme instancias en el plan usado; un checkpointer en memoria perdería toda sesión activa en cada redeploy o cold start.

Supabase Postgres desacopla el estado de conversación del proceso: la sesión sobrevive reinicios y, a futuro, permite escalar a más de una instancia sin perder continuidad de diálogo.

Decisiones de stack, no defaults

FIG. 03 — TECNOLOGÍA

Cada componente se eligió por una razón arquitectónica concreta, no por popularidad.

FastAPI API

Routers modulares, OpenAPI autogenerado, compatible con el estándar abierto Open Responses (/v1/responses) y streaming SSE.

Qdrant Cloud Vectores

Búsqueda por similitud coseno con metadatos filtrados por tipo, en vez de retrieval semántico ciego sobre todo el corpus.

Groq LPU + HF Router LLM

Conmutación automática entre proveedores para alta disponibilidad, con latencias de generación por debajo de 600 ms en el proveedor principal.

LangGraph Orquestación

Grafo de estados explícito en vez de una cadena implícita — cada nodo es testeable y trazable por separado.

Supabase Postgres Persistencia

PostgresSaver mapea la conversación por session_id, con memoria de diálogo real entre turnos sin duplicar mensajes en el prompt.

Langfuse SDK v3 Tracing

Registra explícitamente qué chunks se recuperaron y con qué score en cada turno — la evidencia detrás de cada respuesta.

Prometheus / Grafana Cloud Métricas

Latencia por nodo, tokens y costo por proveedor, salud de proceso — expuesto en /metrics con token propio.

slowapi Protección

Rate limiting de 60 req/min para prevenir abuso y consumo acelerado de cuota de LLM.

Los guardrails, en acción

FIG. 04 — COMPORTAMIENTO

Cinco casos reales que muestran dónde el sistema afirma con seguridad, dónde se niega, y dónde falla ruidosamente en vez de inventar.

IN-BOUNDS → "¿Qué experiencia tiene Diego en Inteligencia Artificial?" Responde con seguridad, anclado a los chunks de experiencia: Teradata, LangGraph, conectores MCP/FastMCP.
ANÁFORA → "¿Y cuánto tiempo estuvo ahí?" El clasificador resuelve "ahí" = Teradata usando el historial de sesión y aplica la regla de tiempo pasado.
CONTACTO → "¿Cómo puedo contactar a Diego?" Recupera el chunk explícito de contacto — nunca lo infiere ni lo aproxima.
OUT-OF-DOMAIN → "¿Cuál es la receta para tacos al pastor?" Corta la ejecución en el clasificador de intención — no gasta tokens ni consulta Qdrant.
FAIL-LOUD → Falla de red hacia el servicio de embeddings (0 chunks recuperados) "En este momento no pude acceder a los datos de la base de conocimiento. Por favor, intenta de nuevo." — nunca improvisa.
